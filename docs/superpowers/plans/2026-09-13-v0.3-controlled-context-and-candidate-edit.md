# v0.3 可控上下文与候选编辑

## 目标

让作者继续只输入故事想法，同时获得两项可控能力：

1. 在发送给当前 Provider 前，按条目选择本地长篇记忆，或保留自动推荐；
2. 在候选正文进入正式正文前编辑并查看逐行 Diff，编辑后必须重新审核。

完成标准：选择配置在 production run 和 candidate 上可追溯并参与上下文 hash；Provider prompt 只包含允许发送的记忆；候选正文编辑有乐观锁、revision 冲突提示且不直接改正式正文；全部 API、Electron IPC、UI 和回归测试通过。

## 边界

- 仍然保持本地优先、候选先审后采纳；不提供角色卡式手填流程。
- “仅发送选中”只接受当前作品中非归档的记忆条目；空选择合法并表示本次不发送记忆。
- 选择配置按 production run 冻结，不新增跨作品共享、不把记忆同步到云端、不引入向量数据库。
- 候选编辑只修改隔离的 candidate_text；保存会清空旧 review/memoryDelta，重新审核通过后才可 accept。
- 每次编辑使用 candidate text revision 乐观锁；正文 accept 仍必须使用 chapter expectedRevision，并保留章节快照。
- API Key 继续只存在既有 Provider 会话/Vault 边界，不写入数据库、日志、候选、备份、导出或响应。
- Electron 继续使用白名单 IPC、contextIsolation、nodeIntegration=false、sandbox=true；不做无关桌面重构。
